# 캔들 관찰 스크립트 개선 계획

## 배경

`scripts/run_candlestick_observation.py`의 `daily` 모드는 현재 `observations_added` 출력 이후에도 오래 실행될 수 있다. 이유는 관찰 로그 업데이트 단계에서 기존 행을 다시 순회하면서 각 행마다 OHLCV를 재조회하기 때문이다.

## 목표

1. 실행 중간 진행 상황을 확인할 수 있게 한다.
2. 같은 티커와 비슷한 기간의 OHLCV를 반복 조회하지 않도록 줄인다.
3. `scan`, `update`, `summary`, `daily`를 명확히 분리해 필요한 단계만 실행할 수 있게 한다.

## 작업 계획

### 1) 진행률 로그 추가

- `update_observations()`에 전체 처리 건수와 현재 처리 인덱스를 출력한다.
- 일정 간격으로 현재까지 변경된 필드 수와 스킵 건수를 함께 보여준다.
- 멈춘 것처럼 보이는 구간이 실제로 어디인지 식별할 수 있게 한다.

### 2) OHLCV 중복 조회 최소화

- `update_observations()`에서 행마다 `fetch_ohlcv()`를 다시 부르지 않도록 바꾼다.
- 동일 티커에 대해 필요한 기간을 묶어 한 번만 가져오고, 이후에는 메모리 내에서 재사용한다.
- 가능하면 티커 단위 캐시를 두고, 관찰 로그의 각 행은 같은 캐시 결과를 참조하게 한다.

### 3) 모드 분리 정리

- `scan`은 패턴 탐지와 관찰 후보 추가만 담당한다.
- `update`는 기존 관찰 로그를 갱신만 담당한다.
- `summary`는 요약 CSV와 Markdown 생성만 담당한다.
- `daily`는 위 세 단계를 순서대로 실행하는 오케스트레이션 역할만 유지한다.

## 검증 기준

- `scan`만 실행하면 스캔 산출물만 갱신된다.
- `update`만 실행하면 기존 관찰 로그의 후속 지표만 갱신된다.
- `summary`만 실행하면 요약 파일만 갱신된다.
- `daily` 실행 시 중간 진행률이 보이고, 이전보다 실행 시간이 줄어든다.

## 기대 효과

- “멈춘 것처럼 보이는” 문제가 줄어든다.
- 대량 관찰 로그 처리 시간이 줄어든다.
- 필요한 단계만 재실행할 수 있어 재현성과 운영성이 좋아진다.
