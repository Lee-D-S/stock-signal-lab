# 1인 투자 기업 운영 데이터 매뉴얼

작성일: 2026-05-08

## 1. 목적

이 문서는 `FreeAgentPipeline`을 실제 운영할 때 필요한 입력 데이터를 정리한다.

현재 투자팀은 다음 순서로 동작한다.

```text
QuantSignalAgent
→ EquityResearchAnalystAgent
→ ResearchFileAgent
→ PortfolioManagerAgent
→ RiskManagerAgent
→ ComplianceOfficerAgent
→ TraderAgent
→ OperationsReportAgent
```

이 Pipeline은 자동 주문 시스템이 아니다. 목적은 후보, 리서치, 계좌, 리스크, 준법, 주문안, 운영 보고를 빠짐없이 기록하는 것이다.

## 2. 데이터가 부족하면 생기는 일

데이터가 없으면 Pipeline은 중단하지 않는다. 대신 해당 Agent가 `needs_review` 또는 `block`을 기록하고 Trader는 `hold`를 만든다.

| 부족한 데이터 | 주로 영향받는 Agent | 결과 |
|---|---|---|
| 후보 없음 | Quant, Trader, Operations | 후보 0개 보고서 생성 |
| 현재가 없음 | Quant, Trader | 수량 계산 불가, `hold` 가능 |
| 거래대금 없음 | Quant, Risk | 유동성 판단 불가, `needs_review` |
| 섹터 없음 | Risk | 섹터 집중도 판단 불가, `needs_review` |
| 포트폴리오 JSON 없음 | Portfolio, Risk | 계좌 판단 불가, `hold` |
| 리서치 파일 없음 | Analyst, ResearchFile, Compliance | 근거 부족, `needs_review` |
| 리서치 필수 섹션 없음 | Analyst, ResearchFile, Compliance | 분석/기록 미완성 |
| 금지/주의 키워드 | Analyst, ResearchFile, Compliance | 사람 검토 또는 `block` |

정상 운영 목표는 모든 후보가 자동 `buy`가 되는 것이 아니다. 데이터가 부족할 때 정확히 `hold`가 되는 것이 정상 동작이다.

## 3. 필수 데이터 세트

### 3.1 후보 데이터

후보 데이터는 “오늘 검토할 종목”이다.

현재 CLI 수동 입력 형식:

```powershell
rtk python scripts/run_free_agent_pipeline.py --candidate 005930:삼성전자:100000
```

현재 수동 후보가 담는 값:

| 필드 | 예시 | 설명 |
|---|---|---|
| `ticker` | `005930` | 6자리 종목코드 |
| `name` | `삼성전자` | 종목명 |
| `suggested_amount` | `100000` | 검토용 주문 금액 |
| `source` | `cli` | 수동 입력 출처 |
| `source_type` | `manual` | 수동 후보 |

현재 수동 입력으로는 아래 값이 들어가지 않는다.

| 필드 | 필요한 이유 |
|---|---|
| `current_price` | Trader 수량 계산 |
| `trade_amount` | Risk 유동성 검사 |
| `sector` | Risk 섹터 집중도 검사 |
| `signal_details` | Quant 신호 근거 추적 |

따라서 수동 후보만 넣으면 `needs_review`가 나오는 것이 자연스럽다.

후보 데이터의 이상적인 구조:

```json
{
  "ticker": "005930",
  "name": "삼성전자",
  "source": "daily_signal_csv",
  "source_type": "scoring",
  "score": 82.5,
  "suggested_amount": 100000,
  "signal_count": 3,
  "signal_details": [
    {
      "source_file": "ai 주가 변동 원인 분석/07_전략신호/example.csv",
      "signal_date": "2026-05-08",
      "condition": "value_momentum_confirmed"
    }
  ],
  "current_price": 80000,
  "trade_amount": 120000000000,
  "sector": "반도체"
}
```

운영 기준:

- 수동 후보는 빠른 테스트용으로 사용한다.
- 실제 운영은 `--discover`로 전략 신호 CSV에서 후보를 가져오는 방식이 더 낫다.
- 향후에는 후보 JSON/CSV 입력을 확장해 `current_price`, `trade_amount`, `sector`를 직접 넣을 수 있게 하는 것이 좋다.

### 3.2 포트폴리오 데이터

포트폴리오 JSON은 현재 계좌 상태다.

예시 경로:

```text
data/portfolio_snapshot.json
```

예시:

```json
{
  "cash": 1000000,
  "positions": [
    {
      "ticker": "005930",
      "name": "삼성전자",
      "quantity": 10,
      "avg_price": 70000,
      "current_price": 80000,
      "sector": "반도체"
    }
  ]
}
```

필드 설명:

| 필드 | 필수 | 설명 |
|---|---:|---|
| `cash` | 예 | 주문 가능 현금 |
| `positions` | 예 | 현재 보유 종목 목록 |
| `ticker` | 예 | 6자리 종목코드 |
| `name` | 아니오 | 종목명 |
| `quantity` | 예 | 보유 수량 |
| `avg_price` | 아니오 | 평균 매입가 |
| `current_price` | 아니오 | 현재가 또는 평가 기준 가격 |
| `sector` | 아니오 | 섹터 |

포트폴리오 데이터가 있으면 가능한 검사:

- 현금 부족 여부
- 기존 보유 종목 여부
- 주문 후 종목 비중
- 주문 후 섹터 비중
- 계좌 전체 가치

미래에셋 계좌처럼 계좌 API를 직접 연결하지 못하는 경우:

1. `data/manual_portfolio_input.json`에 보유수량, 평균단가, 예수금을 입력한다.
2. KIS 시세 API로 현재가, 거래대금, PER/PBR을 보강한다.
3. `data/portfolio_snapshot.json`을 생성한다.

보강 명령:

```powershell
rtk python scripts/build_portfolio_snapshot.py
```

생성 결과:

```text
data/portfolio_snapshot.json
```

실행 예시:

```powershell
rtk python scripts/run_free_agent_pipeline.py --candidate 005930:삼성전자:100000 --portfolio-json data\portfolio_snapshot.json --research-root "ai 주가 변동 원인 분석\00_기업별분석"
```

운영 기준:

- 포트폴리오 JSON은 실행 전 최신 상태로 갱신한다.
- `cash`는 총 예수금이 아니라 실제 주문 가능 현금 기준으로 넣는다.
- `current_price`가 없으면 `avg_price`로 market value를 계산하지만 정확도가 떨어진다.
- 섹터가 없으면 Risk가 섹터 집중도를 판단하지 못한다.

### 3.3 리서치 파일 데이터

리서치 파일은 후보 기업에 대한 분석 근거다.

기본 위치:

```text
ai 주가 변동 원인 분석/00_기업별분석/
```

예시:

```text
00_기업별분석/
  삼성전자/
    삼성전자_2025_Q4_원인후보_실제분석.md
    삼성전자_2025_Q4_events.jsonl
```

현재 품질 검사 대상 확장자:

| 확장자 | 사용 |
|---|---|
| `.md` | 리서치 본문 |
| `.txt` | 보조 리서치 텍스트 |
| `.csv` | 보조 데이터 |

필수 리서치 섹션:

| 내부 키 | 사람이 써야 하는 내용 |
|---|---|
| `business_model` | 무엇으로 돈을 버는가 |
| `investment_thesis` | 왜 투자 후보인가 |
| `risk` | 틀릴 수 있는 이유 |
| `disconfirmation` | 어떤 조건이면 가설을 버릴 것인가 |

Analyst가 추가로 확인하는 항목:

| 항목 | 설명 |
|---|---|
| `earnings_quality` | 최근 실적과 이익의 질 |
| `balance_sheet` | 부채, 현금, 차입 등 재무 안정성 |
| `valuation` | PER/PBR/EV/EBITDA, 과거 밴드, peer 비교 |
| `catalyst` | 실적, 수주, 정책, 공시, 업황 등 촉매 |

운영 기준:

- 리서치 파일이 없어도 Pipeline은 실행된다.
- 다만 ResearchFile/Compliance가 `needs_review`를 내고 Trader는 `hold`가 된다.
- 리서치가 오래됐거나 필수 섹션이 없으면 자동 승인하지 않는다.
- 목표주가는 현재 v1 범위가 아니다. 우선은 밸류에이션 근거 품질을 확인한다.

### 3.4 시장 데이터

시장 데이터는 후보 판단과 리스크 검사에 필요하다.

| 데이터 | 사용 Agent | 목적 |
|---|---|---|
| 현재가 | Quant, Trader | 수량 계산 |
| 거래대금 | Quant, Risk | 유동성 검사 |
| PER/PBR/EPS/BPS | Analyst, 리서치 스크립트 | 밸류에이션 참고 |
| OHLCV | 기존 전략/신호 스크립트 | 후보 발굴 |
| 투자자 수급 | 기존 전략/신호 스크립트 | 후보 발굴 |

현재 Agent Pipeline 자체는 실시간 API를 직접 호출하지 않는다. 기존 스크립트와 산출 파일이 만든 데이터를 사용한다.

운영 기준:

- 수동 후보에는 시장 데이터가 거의 없으므로 테스트용으로 본다.
- 실제 운영은 기존 신호 생성 파이프라인이 만든 CSV 후보를 사용한다.
- `trade_amount`가 없으면 Risk는 유동성 판단 불가로 `needs_review`를 낸다.

### 3.5 정책 데이터

현재 정책은 CLI 옵션과 `config.py` 설정으로 들어간다.

주요 설정:

| 설정 | 기본 의미 |
|---|---|
| `--default-amount` | 후보 금액이 없을 때 기본 검토 금액 |
| `--max-position-pct` | 주문 후 종목 최대 비중 |
| `--max-sector-pct` | 주문 후 섹터 최대 비중 |
| `--max-daily-new-buy-amount` | 일간 신규 매수 총액 한도 |
| `--no-require-research-file` | 리서치 파일 필수 조건 해제 |

운영 기준:

- 실전 검토에서는 `--no-require-research-file`을 쓰지 않는 것이 기본이다.
- 향후 `policy/risk_policy.json`, `policy/compliance_policy.json`으로 분리하는 것이 좋다.

## 4. Agent별 필요한 데이터

| Agent | 꼭 필요한 데이터 | 없을 때 |
|---|---|---|
| QuantSignalAgent | 후보, source, 가격/거래대금/신호 상세 | warnings, `needs_review` 가능 |
| EquityResearchAnalystAgent | 후보 ticker/name, 리서치 파일 | `analysis_status=missing/partial` |
| ResearchFileAgent | 리서치 루트, 기업별 파일 | `quality_status=missing/incomplete` |
| PortfolioManagerAgent | 포트폴리오 JSON, Analyst/Research 결과 | 신규 후보 `hold` |
| RiskManagerAgent | 현금, 포트폴리오 가치, 금액, 섹터, 거래대금 | `needs_review` 또는 `block` |
| ComplianceOfficerAgent | ticker/source, 리서치, Analyst/Research 일치성 | `needs_review` 또는 `block` |
| TraderAgent | Portfolio/Risk/Compliance 결과, 현재가 | `hold`, 수량 0 |
| OperationsReportAgent | 모든 AgentResult | 누락 Agent를 보고서에 기록 |

## 5. 운영 전 체크리스트

매일 실행 전:

- 후보 생성 파일이 최신인지 확인한다.
- 기준일은 오늘 또는 과거 재현 가능한 날짜만 사용한다. 미래 날짜는 미래 시세나 미래 매매 판단을 뜻하지 않으며 기본 실행에서 차단된다.
- 포트폴리오 JSON의 `cash`, `positions`, `current_price`, `sector`를 갱신한다.
- 기업별 리서치 파일이 존재하는지 확인한다.
- 신규 후보는 리서치 파일 필수 섹션이 있는지 확인한다.
- 리스크 한도 설정이 현재 투자 원칙과 맞는지 확인한다.
- 실제 주문 API 호출이 없다는 전제를 유지한다.

실행 후:

- `final_committee_report.md`를 먼저 읽는다.
- `trader_order_proposal.json`에서 `side`, `final_side_reason`, `risk_status`, `compliance_status`를 확인한다.
- `pipeline_manifest.json`에서 `broker_api_called=false`를 확인한다.
- `RiskManagerAgent`와 `ComplianceOfficerAgent` warnings를 확인한다.
- `hold` 후보를 실수로 주문하지 않는다.

## 6. 권장 실행 순서

### 6.1 빠른 수동 테스트

```powershell

```

예상:

- 포트폴리오 JSON이 없으므로 Portfolio/Risk가 `needs_review`
- Trader는 `hold`
- 보고서는 정상 생성

### 6.2 포트폴리오 포함 테스트

```powershell
rtk python scripts/run_free_agent_pipeline.py --candidate 005930:삼성전자:100000 --portfolio-json data\portfolio_snapshot.json --research-root "ai 주가 변동 원인 분석\00_기업별분석"
```

예상:

- 계좌 판단은 더 정확해진다.
- 수동 후보에 `current_price`, `trade_amount`, `sector`가 없으면 여전히 `needs_review` 가능성이 높다.

### 6.3 전략 신호 기반 실행

```powershell

```

예상:

- 후보 source와 signal_details가 수동 입력보다 풍부하다.
- CSV에 가격/거래대금/점수 필드가 있으면 Quant/Risk 판단 품질이 좋아진다.

## 8. 현재 부족한 운영 데이터와 개선 우선순위

현재 가장 큰 공백:

1. 수동 후보 입력이 `current_price`, `trade_amount`, `sector`를 받지 못한다.
2. 미래에셋 계좌 원천 정보는 수동 입력이 필요하다.
3. 리서치 파일은 존재하지만 필수 투자 가설 템플릿이 완전히 표준화되어 있지 않다.
4. Risk/Compliance 정책이 별도 JSON 파일로 분리되어 있지 않다.

개선 우선순위:

1. 후보 JSON 또는 후보 CSV 입력 지원
2. `data/manual_portfolio_input.json`에서 `data/portfolio_snapshot.json` 자동 생성 고도화
3. 기업 리서치 표준 템플릿 추가
4. Risk/Compliance policy JSON 분리
5. 후보/포트폴리오/리서치 데이터 검증 스크립트 추가

## 9. 운영 원칙

- 데이터가 부족하면 매수하지 않는다.
- `needs_review`는 실패가 아니라 사람 검토가 필요하다는 뜻이다.
- `block`은 명확한 차단 사유다.
- Trader가 `buy`를 만들더라도 실제 주문은 별도 수동 행동이다.
- `broker_api_called=false`가 유지되어야 한다.
- 보고서는 투자 지시가 아니라 투자위원회 검토 기록이다.
- `--date`와 `--as-of-date`는 투자 판단 기준일이다. 해당 날짜의 미래 데이터를 가져오거나 미래 매수/매도 종목을 예측하는 기능이 아니다.
