# 1인 투자기업 AI Agent 시스템 PLAN

작성일: 2026-05-07

## 1. 목적

이 문서는 주식 투자를 시작점으로 하는 1인 투자기업의 AI Agent 운영 체계를 설계하기 위한 상위 계획이다. 목표는 큰 자산운용사/투자운용사의 역할을 1인 기업에 맞게 축소하고, 각 역할을 AI Agent로 분리해 투자 판단과 운영을 체계화하는 것이다.

초기 목표는 실제 자동주문이 아니다. 우선 다음 흐름을 안정적으로 만든다.

```text
리서치
→ 후보 발굴
→ 포트폴리오 제안
→ 리스크/준법 검토
→ 주문안 생성
→ 사람 승인
→ 기록/보고
```

핵심 원칙은 다음과 같다.

- AI Agent는 역할별로 분리한다.
- 초기에는 모든 Agent가 실제 주문을 실행하지 않는다.
- 실제 주문 권한은 사람에게 둔다.
- Risk/Compliance Agent는 단순 조언이 아니라 차단 권한을 가진다.
- 투자 판단, 주문 제안, 승인, 기록은 서로 분리한다.
- Codex subagent는 개발 보조용으로 쓰고, 투자 운영 Agent는 앱 내부 런타임으로 만든다.

## 2. 전체 Agent 구조

초기 버전은 8개 Agent로 구성한다.

| Agent | 역할 |
|---|---|
| `InvestmentCommitteeAgent` | 전체 흐름 조율, 최종 투자위원회 판단 |
| `ResearchAnalystAgent` | 기업/산업/공시/뉴스 분석, 투자 가설 작성 |
| `QuantSignalAgent` | 스크리닝, 가격/거래량 신호, 백테스트 요약 |
| `PortfolioManagerAgent` | 포트폴리오 관점의 비중/매수/매도 제안 |
| `RiskManagerAgent` | 손실한도, 집중도, 유동성, 변동성 검사 |
| `ComplianceOfficerAgent` | 투자근거, 금지행위, 기록 누락, 규칙 위반 검사 |
| `TraderAgent` | 주문안 생성, 체결 비용/호가/분할주문 검토 |
| `OperationsReportAgent` | 포지션/현금 대사, 일간/월간 보고서 생성 |

초기에는 `OperationsAgent`와 `ReportAgent`를 하나로 묶어 복잡도를 낮춘다. 나중에 실제 체결, 회계, 세금, 보고가 커지면 두 역할을 분리한다.

## 3. 역할별 큰 책임

### InvestmentCommitteeAgent

전체 Agent의 결과를 모아 최종 투자위원회 요약을 만든다. 각 Agent의 의견이 충돌할 경우 사람에게 확인이 필요한 항목을 명확히 표시한다.

주요 산출물:

- 최종 투자 판단 요약
- 매수/매도/보류 의견
- 사람 승인 필요 항목
- Risk/Compliance 차단 사유 요약

### ResearchAnalystAgent

기업과 산업을 분석하고 투자 가설을 만든다. 뉴스, 공시, 실적, 재무제표, 밸류에이션, 경쟁구도 등을 정리한다.

주요 산출물:

- 기업 분석 요약
- 투자 가설
- 반증 조건
- 주요 리스크
- 추적할 이벤트

### QuantSignalAgent

가격, 거래량, 재무 팩터, 기술적 조건, 백테스트 결과를 정리한다. 기존 `scripts/`의 스크리닝, 백테스트, 관찰 파이프라인과 가장 먼저 연결할 수 있는 Agent다.

주요 산출물:

- 스크리닝 결과
- 신호 강도
- 과거 성과 요약
- 데이터 품질 경고
- 모델/조건의 한계

### PortfolioManagerAgent

개별 종목의 매력도보다 포트폴리오 전체 관점에서 판단한다. 현재 보유 비중, 현금 비중, 섹터 노출, 기존 투자 가설과의 관계를 고려해 매수/매도/보류를 제안한다.

주요 산출물:

- 목표 비중 제안
- 매수/매도/보류 의견
- 현금 비중 의견
- 기존 보유 종목과의 충돌 여부

### RiskManagerAgent

손실 가능성과 포트폴리오 훼손 가능성을 검사한다. 이 Agent는 제안만 하지 않고, 기준을 위반하면 주문안을 차단할 수 있어야 한다.

주요 산출물:

- `approve`, `block`, `needs_review` 중 하나의 결과
- 종목/섹터/전략 집중도 점검
- 손실한도 점검
- 유동성 점검
- 차단 사유

### ComplianceOfficerAgent

투자 판단의 절차적 정합성을 검사한다. 미공개정보, 루머, 투자근거 누락, 기록 누락, 금지행위 가능성을 점검한다.

주요 산출물:

- `approve`, `block`, `needs_review` 중 하나의 결과
- 투자근거 충족 여부
- 기록 요건 충족 여부
- 금지행위 또는 주의 필요 항목

### TraderAgent

초기에는 실제 주문을 실행하지 않고 주문안만 만든다. 호가, 거래대금, 예상 체결 비용, 분할주문 필요성을 검토한다.

주요 산출물:

- 주문 방향
- 제안 수량 또는 금액
- 지정가/분할/관망 제안
- 체결 비용 고려사항
- 주문 전 사람이 확인할 체크리스트

### OperationsReportAgent

투자 판단과 주문안, 승인 여부, 포지션 변화를 기록하고 보고서를 만든다.

주요 산출물:

- 일간 운용 요약
- 주간 후보/보유 종목 리뷰
- 월간 성과/실수/개선점 리포트
- Agent 실행 로그 요약

## 4. 실행 흐름

초기 투자 판단 흐름은 고정한다.

```text
1. ResearchAnalystAgent
   기업/뉴스/공시/재무 분석

2. QuantSignalAgent
   가격/거래량/팩터/백테스트 신호 확인

3. PortfolioManagerAgent
   현재 포트폴리오 기준으로 매수/매도/보류 제안

4. RiskManagerAgent
   비중, 손실한도, 유동성, 집중도 검사

5. ComplianceOfficerAgent
   투자근거, 금지행위, 기록 요건 검사

6. TraderAgent
   실제 주문이 아닌 주문안 생성

7. 사용자 승인
   사람이 최종 확인

8. OperationsReportAgent
   기록 저장, 보고서 생성
```

초기 성공 기준은 AI가 직접 주문하는 것이 아니다. 사람이 승인할 수 있는 수준의 주문안과 판단 근거를 일관되게 생성하는 것이다.

## 5. 기술 방향

투자 운영 Agent는 앱 내부 기능으로 만든다.

| 필요 기능 | 기술 방향 |
|---|---|
| Agent 실행 | OpenAI Agents SDK 또는 Responses API |
| Agent 간 역할 위임 | handoffs 또는 명시적 orchestrator 호출 |
| 외부 기능 연결 | custom tools |
| 표준 출력 | structured output(JSON) |
| 위험 차단 | 코드 기반 guardrails |
| 실행 추적 | tracing/logging |
| 리서치 문서 검색 | 기존 분석 문서와 `docs/` 기반 검색 |

Codex subagent와 `VoltAgent/awesome-codex-subagents`는 투자 운영 런타임이 아니라 개발 보조에 사용한다.

예시:

- 코드 설계 검토
- 보안/리스크 리뷰
- 문서 작성
- 테스트 보강
- 리팩터링 보조

## 6. 프로젝트 내 권장 구조

초기 구현 시에는 다음 구조를 기준으로 잡는다.

```text
core/agents/
  투자 Agent 정의와 orchestration

core/agent_tools/
  가격 조회, 포트폴리오 조회, 리서치 조회, 리스크 검사 도구

core/guardrails/
  주문금액, 비중, 손실한도, 유동성, 투자근거 검사

models/
  Agent 실행 기록, 투자 판단 기록, 주문안 기록

scripts/
  Agent 파이프라인 실행용 CLI

docs/
  운영 정책, 역할별 PLAN, 내부통제 문서
```

실제 파일명과 세부 클래스명은 구현 단계에서 기존 코드 스타일에 맞춰 정한다. 다만 `core/agents`, `core/agent_tools`, `core/guardrails`의 경계는 유지한다.

## 7. 구축 단계

### Phase 1. 문서/정책 기반 설계

목표: 구현 전에 운영 원칙을 고정한다.

산출물:

- 전체 Agent 아키텍처 문서
- 투자 판단 흐름도
- 주문 권한 정책
- 리스크/준법 기본 규칙
- 역할별 상세 PLAN 작성 순서

우선 상세화할 역할 순서:

1. `ResearchAnalystAgent`
2. `QuantSignalAgent`
3. `PortfolioManagerAgent`
4. `RiskManagerAgent`
5. `ComplianceOfficerAgent`
6. `TraderAgent`
7. `OperationsReportAgent`
8. `InvestmentCommitteeAgent`

### Phase 2. 읽기 전용 Agent 프로토타입

목표: 주문 없이 분석과 제안만 수행한다.

기능:

- 보유/관심 종목 입력
- 리서치 요약 생성
- 퀀트 신호 요약
- 포트폴리오 매수/매도/보류 제안
- 리스크/준법 검토 결과 생성
- 최종 주문안 대신 검토용 액션 카드 생성

이 단계에서는 모든 Agent가 읽기 전용 도구만 사용한다.

### Phase 3. 리스크/준법 Gate 구축

목표: 투자 판단보다 먼저 차단 규칙을 신뢰 가능하게 만든다.

기본 차단 규칙:

- 종목 최대 비중 초과
- 섹터 최대 비중 초과
- 일간 손실한도 초과
- 거래대금 대비 주문금액 과다
- 투자 가설/근거 누락
- 실적 발표, 거래정지, 관리종목 등 이벤트 리스크
- 자동화 오류 또는 데이터 누락

Risk/Compliance 결과는 `approve`, `block`, `needs_review` 중 하나로 표준화한다.

### Phase 4. 주문안 생성

목표: 실제 주문이 아니라 사람이 승인할 수 있는 주문안을 만든다.

주문안 포함 항목:

- 종목코드/종목명
- 매수/매도 방향
- 제안 수량 또는 금액
- 주문 방식: 지정가/분할/관망
- 주문 근거
- 리스크 검사 결과
- 준법 검사 결과
- 사람이 확인해야 할 항목

초기에는 한국투자증권 API 주문 호출과 연결하지 않는다. 주문 API 연결은 별도 Phase로 둔다.

### Phase 5. 운영 기록/보고 자동화

목표: 모든 판단과 결과를 나중에 복기 가능하게 만든다.

기록 대상:

- Agent별 입력/출력
- 투자 가설
- 리스크/준법 검사 결과
- 주문안
- 사용자 승인 여부
- 실제 체결 여부
- 사후 성과

보고서:

- 일간 운용 요약
- 주간 후보 종목/보유 종목 리뷰
- 월간 성과/실수/개선점 리포트

## 8. 초기 테스트 계획

초기 테스트는 실제 주문 없이 진행한다.

- 특정 종목 1개를 넣었을 때 리서치 요약이 생성되는지 확인한다.
- 관심종목 리스트를 넣었을 때 퀀트 신호가 표준 형식으로 나오는지 확인한다.
- 포트폴리오 비중 초과 상황에서 `RiskManagerAgent`가 차단하는지 확인한다.
- 투자근거가 비어 있을 때 `ComplianceOfficerAgent`가 차단하는지 확인한다.
- 모든 Agent 결과가 하나의 최종 투자위원회 요약으로 합쳐지는지 확인한다.
- 주문안 생성 결과에 필수 필드가 모두 포함되는지 확인한다.
- 실행 로그를 통해 왜 이 제안이 나왔는지 추적 가능한지 확인한다.

## 9. 가정과 제외 범위

가정:

- 초기 대상 자산은 국내/해외 주식으로 제한한다.
- 초기에는 자기자본 운용만 전제로 한다.
- 각 Agent별 상세 PLAN은 후속 문서로 따로 작성한다.
- 운영 Agent는 개발용 Codex subagent가 아니라 앱 내부 런타임으로 구현한다.

제외 범위:

- 타인 자금 운용
- 투자자문/투자일임/펀드 설정
- 실제 자동주문
- 부동산, 채권, 보험 등 주식 외 자산군
- 인허가/법무/세무 세부 검토
