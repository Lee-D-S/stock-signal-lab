# 현재 실행 가능 기능과 자동화 정리

이 문서는 현재 코드 기준으로 실행 가능한 주요 기능, 스크립트, 명령어와 `morning`/`daily` 자동화에 포함된 작업을 정리한다.

## 기준 파일

- GitHub Actions 자동화: `.github/workflows/daily_auto.yml`
- 통합 리서치 파이프라인: `scripts/run_signal_research_pipeline.py`
- 로컬 앱 스케줄러: `scheduler/runner.py`
- 대시보드 앱: `dashboard/main.py`

## 앱과 대시보드

### 전체 앱 실행

```bash
rtk python main.py
```

처리 내용:

- SQLite DB 초기화
- 증권사 실제 잔고를 로컬 `Position` DB와 동기화
- APScheduler 시작
- FastAPI 대시보드 실행

### 대시보드/API만 실행

```bash
rtk python -m uvicorn dashboard.main:app --reload
```

현재 확인된 주요 API:

- `GET /health`
- `GET /positions`
- `GET /positions/realtime`
- `GET /trades`
- `GET /strategies`
- `POST /strategies/{name}/toggle`
- `POST /strategies/{name}/tickers`
- `GET /market/sectors`
- `GET /market/sector-signals`
- `GET /market/sector-accuracy`

## 로컬 앱 스케줄러

`rtk python main.py`로 앱이 떠 있을 때 `scheduler/runner.py`의 APScheduler가 실행한다.

|---|---:|---|---|
| `ma_cross` | 5분마다 | 이동평균 교차 전략 실행 | 현재 전략 인스턴스는 `enabled=False` |
| `news_crawl` | 기본 10분마다 | 뉴스 크롤링 및 AI 분석 | `settings.news_crawl_interval_min` 기준 |

| `daily_summary` | 평일 15:35 | 일일 매매 손익 텔레그램 요약 | 실행 후 circuit breaker 리셋 |

## 주요 수동 실행 기능

### 스크리닝/리서치

```bash
rtk python scripts/screener.py --by marcap --to 300 --ma-align 60,120,240 --rsi-max 50 --obv-rising

```

### 일일 후보/관찰 파이프라인

```bash
rtk python -u scripts/run_signal_research_pipeline.py --mode daily
rtk python -u scripts/run_signal_research_pipeline.py --mode daily --refresh-universe --recheck
rtk python -u scripts/run_signal_research_pipeline.py --mode daily --date YYYY-MM-DD --refresh-universe --recheck
```

`--mode daily --refresh-universe --recheck` 내부 단계:

1. `scripts/run_daily_universe_refresh.py`
2. `scripts/analyze_per_eps_valuation.py`
3. `scripts/generate_watchlist_signals.py`
4. `scripts/recheck_watchlist_flows.py`
5. `scripts/run_observation_update.py`
6. `scripts/run_foreign_flow_observation.py`
7. `scripts/run_scoring.py --mode screen`
8. `scripts/run_scoring_observation.py`
9. `scripts/run_alignment_observation.py`
10. `scripts/run_ntm_per_observation.py`

밸류에이션 요약은 최신 기업 보고서의 KIS 현재 참고 지표와 KIS 기타 주요 비율을 읽어 PER, PBR, EBITDA, EV/EBITDA를 함께 정리한다. 기존 보고서에 KIS 기타 주요 비율 표가 없으면 EV/EBITDA는 결측으로 남긴다.

NTM PER 관찰은 KIS 현재가와 `estimate-perform` 추정 EPS 테이블을 사용한다. KIS가 `EGW00123` 토큰 만료 응답을 보내면 토큰 캐시를 폐기하고 1회 재발급 후 재시도한다. PEG proxy는 정식 3~5년 EPS 성장률 컨센서스가 아니라 KIS forward EPS 구간의 CAGR proxy를 쓴다.

캔들 패턴 관찰은 수동 보조 점검으로 유지한다. `scripts/run_candlestick_observation.py --mode daily`는 OHLCV 공용 캐시(`data/ohlcv_cache`)를 우선 사용하고 daily 기본 60일만 스캔한다. `--mode history`는 220일 백필을 유지하며, 캐시 무시 재조회가 필요할 때만 `--force-refresh`를 붙인다.

### 문서 동기화 점검

코드 변경 후 관련 운영/기획 문서 업데이트 후보를 확인한다.

```bash
rtk python scripts/check_docs_sync.py --all
```

기본은 추적 중인 변경 파일만 본다. 새로 생성된 기업 리포트 폴더까지 포함해 문서 후보를 보려면 `--include-untracked`를 추가한다.

매핑 파일에 없는 문서까지 폭넓게 후보를 확인하려면 Markdown 관련도 스캔을 함께 실행한다.

```bash
rtk python scripts/check_docs_sync.py --all --scan-md
```

`--scan-md`는 추적 중인 Markdown 문서 전체를 점수화하되, 노이즈가 큰 기업별 생성 보고서와 일일 요약은 기본 제외한다. 생성 Markdown까지 확인해야 할 때만 `--include-generated-md`를 추가한다.

매핑 파일:

- `PLAN/doc_sync_map.json`

현재 매핑은 일일 파이프라인, agent 계획, 밸류에이션/KIS, 외국인 수급, 캔들 관찰, 신규 기업 보고서, 포트폴리오 테스트 데이터, 문서 동기화 도구 변경을 문서 후보로 연결한다.

## GitHub Actions 자동화

워크플로: `.github/workflows/daily_auto.yml`

공통 조건:

- Python 3.12 사용
- `requirements.txt` 설치
- GitHub Secrets에서 KIS, DART, Gemini, Telegram 값을 주입
- 자동 schedule 실행은 한국 주말/공휴일이면 실제 작업을 건너뜀
- 수동 `workflow_dispatch` 실행은 휴장일이어도 실행
- `workflow_dispatch` 입력:
  - `job`: `morning`, `daily`, `both`, `telegram-test`
  - `date`: 기준일 `YYYY-MM-DD`, 비우면 각 스크립트 기본값 사용

## Morning 자동화

GitHub Actions job: `morning-dart-check`

실행 시각:

- 자동: 평일 07:05 KST, 08:35 KST
- cron: `5 22 * * 0-4`, `35 23 * * 0-4`
- 수동: `job=morning` 또는 `job=both`

실행 명령:

```bash
python -u scripts/auto_morning_dart_check.py
```

처리 내용:

1. 한국 거래일 여부 확인
2. 보유 종목, 공통 관찰, 외국인 순매수/순매도 관찰, 신규 조건 관찰, 확정 후보, 외국인 수급 후보, 거래대금 유니버스, 보고서 필요 종목을 합쳐 조회 대상 구성
3. DART 기업코드와 관찰 종목 매칭
4. 마지막 성공 morning 조회 이후 새로 확인 가능한 DART 공시 조회
5. `rcept_no` 기준 신규 공시만 알림 대상으로 분리하고 상세 내용 확인
6. IR, 결산실적공시예고, 주주총회, 배당/기준일 계열 공시에서 미래 이벤트 날짜 추출
7. 관찰 로그와 Markdown 로그에 공시 확인 결과 반영
8. 텔레그램으로 신규 공시와 오늘~3거래일 이내 근일 이벤트 전송
   - 공시 상세가 길면 여러 메시지로 분할 전송
   - 텔레그램 전송 실패 시 job 실패로 처리
9. `ai 주가 변동 원인 분석/` 변경분 커밋 및 `main` push
10. GitHub Actions 성공/실패 텔레그램 알림 전송

주요 산출물:

- `ai 주가 변동 원인 분석/08_관찰기록/00_공통/관찰_로그(이상).csv`
- `ai 주가 변동 원인 분석/08_관찰기록/00_공통/관찰_로그.csv`
- `ai 주가 변동 원인 분석/08_관찰기록/00_공통/관찰_로그.md`
- `ai 주가 변동 원인 분석/08_관찰기록/07_공시이벤트/공시_이벤트_캘린더.csv`
- `ai 주가 변동 원인 분석/08_관찰기록/07_공시이벤트/공시_이벤트_캘린더.md`
- `ai 주가 변동 원인 분석/08_관찰기록/07_공시이벤트/morning_dart_state.json`

커밋 메시지 형식:


## Daily 자동화

GitHub Actions job: `daily-research-pipeline`

실행 시각:

- 자동: 평일 15:55 KST

수동 실행에서 `date` 입력값이 있으면 `--as-of YYYY-MM-DD`가 추가된다.

## 로컬 결과 반영

GitHub Actions가 원격 `main`에 결과를 push한 뒤, 로컬 `C:\projects\auto-invest` 반영은 수동으로 한다.

권장 순서:

```bash
rtk git status --short
rtk git pull --rebase origin main
```

주의:

- 로컬 수정 중인 파일이 있으면 먼저 `rtk git status --short`로 충돌 가능성을 확인한다.
- GitHub Actions가 갱신하는 `ai 주가 변동 원인 분석/` 아래 CSV/MD를 로컬에서 같이 수정 중이면 pull/rebase 충돌이 날 수 있다.

## Free Agent와 테스트 포트폴리오

`scripts/run_agent_committee.py`는 agent 회의/토론 전체 프로세스를 한 번에 실행하는 표준 명령이다. 후보 입력을 명시하지 않으면 기본으로 `--discover`를 적용해 최근 전략 신호 CSV에서 후보를 찾고, 내부적으로 기존 `scripts/run_free_agent_pipeline.py`와 같은 리서치 파일 확인, 애널리스트, 포트폴리오, 리스크, 컴플라이언스, 트레이더, 운영 보고서 단계를 실행한다. 개별 실행이나 세부 옵션 검증이 필요할 때는 기존 `scripts/run_free_agent_pipeline.py` 명령을 그대로 사용할 수 있다.

현재는 검증 agent가 이상을 기록하고 끝내지 않고, 대상 agent에게 피드백을 전달해 1회 재실행한 뒤 `agent_feedback.json`에 해결/미해결 상태를 남긴다.

기본 실행:

```powershell
rtk python -u scripts/run_agent_committee.py --discover-limit 10 --test-portfolio balanced
```

테스트 실행은 실제 자산 포트폴리오 대신 `--test-portfolio balanced|cash-heavy|growth|risk-test`를 사용할 수 있다. 테스트 입력은 `data/portfolios/test_inputs/`의 mock fields만 담고, 현재가·PER/PBR·섹터·거래대금 같은 live fields는 실행 시 KIS 조회로 스냅샷을 만든다. `validate_portfolios_script.py --write-report`는 mock/live/derived fields를 분리해 검증 리포트를 생성한다.

## 주의사항

- 이 문서는 현재 코드에 정의된 실행 가능 항목 기준이다.
- GitHub Actions가 실제 최근 성공했는지 여부는 Actions run 기록을 별도로 확인해야 한다.
- 모든 명령은 이 저장소의 규칙에 따라 `rtk` 접두어를 붙여 실행한다.
