# 현재 실행 가능 기능과 자동화 정리

이 문서는 현재 코드 기준으로 실행 가능한 주요 기능, 스크립트, 명령어와 `morning`/`daily` 자동화에 포함된 작업을 정리한다.

## 기준 파일

- GitHub Actions 자동화: `.github/workflows/daily_auto.yml`
- 통합 리서치 파이프라인: `scripts/run_signal_research_pipeline.py`
- 로컬 앱 스케줄러: `scheduler/runner.py`
- 대시보드 앱: `dashboard/main.py`

## 앱과 대시보드

### 전체 앱 실행

```bash
rtk python main.py
```

처리 내용:

- SQLite DB 초기화
- 증권사 실제 잔고를 로컬 `Position` DB와 동기화
- APScheduler 시작
- FastAPI 대시보드 실행

### 대시보드/API만 실행

```bash
rtk python -m uvicorn dashboard.main:app --reload
```

현재 확인된 주요 API:

- `GET /health`
- `GET /positions`
- `GET /positions/realtime`
- `GET /trades`
- `GET /strategies`
- `POST /strategies/{name}/toggle`
- `POST /strategies/{name}/tickers`
- `GET /market/sectors`
- `GET /market/sector-signals`
- `GET /market/sector-accuracy`

## 로컬 앱 스케줄러

`rtk python main.py`로 앱이 떠 있을 때 `scheduler/runner.py`의 APScheduler가 실행한다.

| 작업 ID | 주기 | 내용 | 비고 |
|---|---:|---|---|
| `ma_cross` | 5분마다 | 이동평균 교차 전략 실행 | 현재 전략 인스턴스는 `enabled=False` |
| `news_crawl` | 기본 10분마다 | 뉴스 크롤링 및 AI 분석 | `settings.news_crawl_interval_min` 기준 |
| `news_sentiment` | 5분마다 | 뉴스 감성 전략 실행 | 현재 전략 인스턴스는 `enabled=False` |
| `daily_summary` | 평일 15:35 | 일일 매매 손익 텔레그램 요약 | 실행 후 circuit breaker 리셋 |
| `sector_crawl` | 10분마다 | 섹터 뉴스 감성 분석 |  |
| `sector_validation` | 평일 15:40 | 섹터 예측 정확도 검증 |  |
| `foreign_flow_observation` | 평일 16:20 | 외국인 연속 순매수 관찰 기록 및 D+ 추적 | `scripts/run_foreign_flow_observation.py` 호출 |

전략 매수/매도 실행은 `is_market_open()` 조건을 따른다.

- 한국 평일
- 한국 공휴일 제외
- 09:00-15:30 KST

## GitHub Actions 자동화

워크플로: `.github/workflows/daily_auto.yml`

공통 조건:

- Python 3.12 사용
- `requirements.txt` 설치
- GitHub Secrets에서 KIS, DART, Gemini, Telegram 값을 주입
- 자동 schedule 실행은 한국 주말/공휴일이면 실제 작업을 건너뜀
- 수동 `workflow_dispatch` 실행은 휴장일이어도 실행
- `workflow_dispatch` 입력:
  - `job`: `morning`, `daily`, `both`, `telegram-test`
  - `date`: 기준일 `YYYY-MM-DD`, 비우면 각 스크립트 기본값 사용

## Morning 자동화

GitHub Actions job: `morning-dart-check`

실행 시각:

- 자동: 평일 08:50 KST
- cron: `50 23 * * 0-4`
- 수동: `job=morning` 또는 `job=both`

실행 명령:

```bash
python -u scripts/auto_morning_dart_check.py
```

처리 내용:

1. 한국 거래일 여부 확인
2. 관찰 로그에서 현재 관찰 중인 종목 읽기
3. DART 기업코드와 관찰 종목 매칭
4. 최근 DART 공시 조회
5. 공시가 있으면 상세 내용 확인 및 Gemini 요약 생성
6. 관찰 로그와 Markdown 로그에 공시 확인 결과 반영
7. 텔레그램으로 결과 전송
8. `ai 주가 변동 원인 분석/` 변경분 커밋 및 `main` push
9. GitHub Actions 성공/실패 텔레그램 알림 전송

주요 산출물:

- `ai 주가 변동 원인 분석/08_관찰기록/관찰_로그(이상).csv`
- `ai 주가 변동 원인 분석/08_관찰기록/관찰_로그.csv`
- `ai 주가 변동 원인 분석/08_관찰기록/관찰_로그.md`

커밋 메시지 형식:

```text
auto: 오전 공시 확인 업데이트 YYYY-MM-DD
```

## Daily 자동화

GitHub Actions job: `daily-research-pipeline`

실행 시각:

- 자동: 평일 16:10 KST
- cron: `10 7 * * 1-5`
- 수동: `job=daily` 또는 `job=both`

실행 순서:

1. 일별 후보 탐지 및 관찰 로그 추가

```bash
python -u scripts/run_signal_research_pipeline.py --mode daily --refresh-universe --recheck
```

수동 실행에서 `date` 입력값이 있으면 `--date YYYY-MM-DD`가 추가된다.

2. 신규 조건 별도 관찰

```bash
python -u scripts/run_new_condition_observation.py --delay 0.35
```

수동 실행에서 `date` 입력값이 있으면 `--date YYYY-MM-DD`가 추가된다.

3. 관찰 로그 D+ 추적 업데이트

```bash
python -u scripts/run_observation_tracking_update.py
```

수동 실행에서 `date` 입력값이 있으면 `--as-of YYYY-MM-DD`가 추가된다.

4. 관찰 성과 요약 생성

```bash
python -u scripts/run_observation_performance_summary.py
```

5. 일일 운영 요약 생성 및 텔레그램 전송

```bash

```

수동 실행에서 `date` 입력값이 있으면 `--date YYYY-MM-DD`가 추가된다.

## 로컬 결과 반영

GitHub Actions가 원격 `main`에 결과를 push한 뒤, 로컬 `C:\projects\auto-invest` 반영은 수동으로 한다.

권장 순서:

```bash
rtk git status --short
rtk git pull --rebase origin main
```

주의:

- 로컬 수정 중인 파일이 있으면 먼저 `rtk git status --short`로 충돌 가능성을 확인한다.
- GitHub Actions가 갱신하는 `ai 주가 변동 원인 분석/` 아래 CSV/MD를 로컬에서 같이 수정 중이면 pull/rebase 충돌이 날 수 있다.

## 자동화 구분 요약

| 구분 | 위치 | 실행 조건 | 주요 역할 |
|---|---|---|---|
| `morning` | GitHub Actions | 평일 08:50 KST | 관찰 종목 DART 공시 확인, 관찰 로그 갱신, 텔레그램 전송 |
| `daily` | GitHub Actions | 평일 16:10 KST | 후보 탐지, 수급 재조회, 관찰 기록, D+ 추적, 성과/일일 요약, 텔레그램 전송 |
| 앱 스케줄러 | `main.py` 실행 중인 로컬 프로세스 | 앱 실행 중 | 장중 전략/뉴스/섹터 분석, 장마감 요약/검증 |
| 로컬 결과 반영 | 수동 명령 | 필요할 때 | `rtk git pull --rebase origin main`으로 GitHub Actions 결과 반영 |

## 주의사항

- 이 문서는 현재 코드에 정의된 실행 가능 항목 기준이다.
- GitHub Actions가 실제 최근 성공했는지 여부는 Actions run 기록을 별도로 확인해야 한다.
- 모든 명령은 이 저장소의 규칙에 따라 `rtk` 접두어를 붙여 실행한다.
